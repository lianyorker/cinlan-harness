## Step 7：REA 原生集成进安全研究

**定位**：REA（rea-agents，MIT）的逆向能力作为 Cinlan Harness **产品内置能力**，跟随"安全研究"组合（`packages/bundle/security-research`）加载。不走外部集成：不让用户 `npm i -g`、不跑 `rea setup`、不手写 `~/.clh` 配置、不依赖 `~/.agents/skills` 里的技能副本。设计与分阶段计划写在 `docs/dev/REA原生集成/plan.md`。

**使用方式：直接说大白话。** 用户在安全研究会话里说"帮我看看这个 exe 是干嘛的""这个 apk 的登录签名怎么算的""反编译一下这个 dll 的 main"，就能直接工作，不需要知道 REA、MCP、工具名或任何命令。达成方式：

1. 产品内置 REA：新建 fork 自有包 `packages/security/security-rea`，精确固定依赖 `rea-agents`，在自身 fiber 里以 stdio 挂载 `@deepseek-ai/dsh-mcp-client`（command 用产品自带的 Node，args 为包内的 `scripts/rea.mjs mcp`），状态目录放在 `<clh home>/security/rea/`，不传 `DSH_HOME`、不碰 `~/.dsh`。
2. 大白话路由：通过 `ctx.skills.register()` 注册产品内置的逆向技能（以 REA 的 reverse-engineer-anything 为底），技能描述补齐中文口语触发词（逆向、反编译、看看这个 exe/dll/so/apk、脱壳、找签名、分析协议、这个程序干嘛的等）；安全研究 preset 和 security-workflow-prompt 写明"用户给出二进制、安装包或网页目标时，直接用 REA 工具取证分析，不要求用户指定工具"。
3. 零配置就绪：启动即自动连接；设置页"安全研究"里加 REA 卡片，只显示状态和检测到的本机工具（Ghidra、JDK、Frida、adb 等），缺什么用大白话提示怎么补，用户不需要填任何路径。
4. 权限：只读的静态分析工具在授权范围内直接可用；会运行目标、改设备或改分析数据的工具走 assessment-scope 审批（细则见计划文档）。
5. 结果用大白话回给用户：结论先行，证据（REA Evidence）作为 finding 附件留存。

**前置阻塞项**：rea-agents 6.8.0 要求 Node `^22.23.4 || ^24.22.1 || >=26.12.1`，本机是 24.9.0。产品运行时版本不满足时，需要先决定是否升级产品的 Node 运行时。
