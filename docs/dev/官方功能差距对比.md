## 一、官方有、我们没有的功能

### 1.1 核心能力（非 experimental，合并优先级高）

| 官方包 | 功能 | 我们的缺口影响 |
|---|---|---|
| `fs/fs-patch` | apply_patch 结构化补丁工具（已带 opt-in 挂载 + observation policy + 快照覆盖） | Agent 改文件能力官方已标准化，我们的 Agent 还靠 shell 写文件 |
| `api/remote-access` | 远程访问 API | **与我们的中继/手机配对计划正面重叠**，见撞车区 |
| `session/message-quotes` | 消息引用 | 会话交互小功能 |
| `core/tool-executor-native` + `tool-executor-ptc` | 原生 / PTC 工具执行器 | 我们有 `experimental/ptc-runtime-python`，执行器层不同，合并时对齐 |
| `context/harness-dev-context` | 开发上下文注入 | 小件 |
| `deliverables/deliverable-file-references` | 交付物文件引用 | 小件 |
| `ssh/ssh-helper-runtime` | SSH 助手运行时 | **里程碑 Phase 2.5 标了"未来工作"的 SSH execution-host，官方做了** |
| `web/web-deepseek-api` | Web 端 DeepSeek 账号登录 | 与 sub2api 账户体系定位不同，需决策并存还是替代 |
| `test-support/tool-testkit` | 测试工具包 | 内部工具 |

## 二、语义撞车区（合并时的决策点）

| 领域 | 我们的 | 官方的 | 建议 |
|---|---|---|---|
| Computer Use | `computer-use/*` + `cinlan-computer-use` + `experimental/computer-use-cua-driver-*` | `experimental/cua` + `cua-bundle` + `cua-macos` | 官方版有 macOS 支持且会维护，评估替换；我们的 cua-driver 若只是驱动层可能可复用 |
| Ralph | `workflow/tool-ralph`（在途） | `experimental/tool-ralph` + `ralph-bundle` | 先对比功能差异再决定，别盲目删我们的 |
| 会话标题 | `session/session-title`（在途） | `session-title-all-prompts-llm` + `session-titles-bundle` | 同上，在途的若功能等价就让位官方 |
| 远程访问/中继 | `cinlan-remote-tunnel` + 移动端配对计划（docs/dev/移动端 + 官方同步/plan.md 第 3 节） | `api/remote-access` + `experimental/liveshare` | **战略级冲突**：官方的 remote-access 是已发布 API 面，我们的中继还没定协议。建议评估在官方 remote-access 上搭我们的手机配对，而不是自研协议 |
| 账号体系 | sub2api（`llm-pi-ai` + `account-controller` + `ui-settings-account`） | `web/web-deepseek-api`（DeepSeek 账号登录） | 定位不同可并存：sub2api 是 Cinlan 自有账户，deepseek-api 是官方登录 |
| SSH | 无（Phase 2.5 推迟） | `ssh/ssh-helper-runtime` | 直接采用官方的，Phase 2.5 缺口被官方填了 |
| hooks/webhook | `packages/hooks/*`、`packages/webhook/*` | 同包挪到 `experimental/` | 纯路径移动，合并时跟官方路径走 |
| 会话持久化 | 计划中的 `session-persistence-sqlite`（Phase 9 未做） | `session-query/session-query-sqlite` 已有 + format v5 演进 | 核对官方 v5 与我们在途 v4-to-v5 的格式是否一致 |

## 五、建议

1. **合并优先拿走的**：`fs/fs-patch`（apply_patch 已是官方标准工具面）、`ssh/ssh-helper-runtime`（填 Phase 2.5 缺口）、`ui-secret-mask` + 凭据脱敏、`util/official-bundles`（插件分发现成机制）
2. **撞车区先评估再动手**：Ralph、会话标题、CUA——我们在途版本若功能不优于官方就放弃，避免双实现；`api/remote-access` vs 中继计划是战略决策，建议先读官方 remote-access 的 API 面再定
3. **不用搬的**：experimental 里的 forge/liveshare/recommendations/cot-translation/stats 等试验品，等官方转正再说；hooks/webhook 只是路径移动
4. **docs/dev 计划里还欠的**：终端迁移整块、通用设置行、Phase 8/9、Gitee provider——这些是 Orca 参考目标，与 upstream 无关，按原计划继续
5. **本文件更新方式**：每次大合并后重跑 `git ls-tree -r upstream/master --name-only packages/ | Select-String 'package\.json$'` 与本地 `Get-ChildItem packages/*/*/package.json` 对比刷新第一、三节
