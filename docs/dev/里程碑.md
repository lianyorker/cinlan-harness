# 里程碑：Orca → DSH 功能迁移

## 一、架构约束

以下内容全部保留，不迁移、不替换：

1. **main 当前目录和包分组结构**
2. **当前 `core / session / agent / tools / api / client / bundle` 分层**
3. **main 的分散式 API controllers**
4. **main 的分散式 Client UI 包**
5. **main 的 Session format adjacent migration 链**
6. **main 的 `subagent-claude-code`、`subagent-codex`、`win32-process`、`authorization`**
7. **main 的 `native/system`、`native/desktop-host`**
8. **所有应用继续通过 `dsh` profile 启动**
9. **agent-loop 不直接修改，新增行为通过插件、Service、Tool、Event 接入**
10. **不新增第二套 Agent、Session、Workspace、API controller、Client state owner**

允许新增的内容只包括：

- 新能力 Service Definition / Provider / Consumer / Bundle
- 新的独立包组
- 当前包的插件扩展
- 面向旧 staged-final 契约的兼容入口
- 当前 profile 的可选 patch layer

## 五、分阶段验收

每个阶段只运行与当前变更匹配的检查：

```text
pnpm run typecheck
pnpm run build
pnpm run lint
pnpm run hygiene
pnpm run duplication
pnpm run test:snapshot
pnpm run test:docs
pnpm run doc-sync
```

最终收口再运行：

```text
pnpm run test
pnpm run test:coverage
pnpm run test:e2e
```

必须额外验证：

- main 现有 profile 仍能启动
- main 独有包未被删除或替换
- Session migration 链未被破坏
- 新增 Service 可卸载
- 所有 model-visible 输入可从 Session log 重建
- 新增 RPC 不绕过 controller
- 新增 Client 不建立第二套 state owner
- 新 Bundle 不产生新的应用入口
- Windows / Linux / macOS 的 Provider 行为分别验证
