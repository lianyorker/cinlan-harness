## 本功能要求

逐项决定保留/不迁移/另设计，禁止把实验目录存在算可用；开发能力须区分 dev 构建、用户偏好与权限，不为 UI 可见性增加越权工具。

保持 Harness 的 Service Definition/Provider/Consumer、Cordis effect、settings slot、Remote 和 Session 日志规则。每个配置字段写明作用域、默认值来源、保存/重置/readback 及失败行为；前后端名字和语义必须一致。模型请求继续经过 Harness LLM API；PTY、SSH、relay、设备和下载分别由资源 owner 管理，不统一替换成 AgentLoop 取消。

先输出映射表、所有同类入口、缺口、拟修改文件及需要的 profile 装配；多包/API/新依赖方案经 Yorker 批准后实施，明确“直接做/继续”时按授权范围执行。无 backend 的产品控件显示 disabled/unavailable，Mock 仅限测试。

## CLH 二开隔离

二开命令、环境与用户根目录使用 `clh`、`CLH_*`/`CLH_HOME`、`~/.clh`，按 [CLH 隔离规则](../提示词使用规则.md#clh-isolation) 列出本功能标识映射、所有同类读写/安装/清理入口和兼容策略；无关项注明不适用。官方源码路径、依赖名和协议字段按实际保留，不做全局字符串替换。

交付本功能的官方 DSH 与 CLH 并存验收收据，禁止占用官方命令或隐式共用数据；历史导入须显式批准。区分规则目标、当前实现与未整改缺口，文档更新不能代替产品隔离实现。

## 行为与 UI 验收

重点测试：生产构建隐藏、权限拒绝、开关恢复、无对应 provider、休眠/唤醒资源状态与卸载。

选择拥有该行为的现有测试文件运行定向检查，记录实际命令/结果。字段或跨层 API 变更扫描所有消费者；新/重构业务模块按项目 MODULE-DELIVERY-GATE，Session/SDK/模型可见输入按仓库持久化与 snapshot 规则处理。UI 验收逐项执行本目录检查表，测试不能替代截图，截图不能替代真实 backend 收据。

## 交付输出

交付源码映射、配置/API 字段表、最小实现路径、实际装配证据、已运行测试结果、截图/操作收据、未验证项和剩余差异。保持 `一致/部分实现/仅有底层能力/缺失/设计不同/待运行验收` 分类，不把源码存在报成完成。
