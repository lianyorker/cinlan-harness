# 提示词使用规则

## 适用范围

本页补充并纠正原始 [全局系统架构提示词](../全局系统架构提示词.md)、[子系统级迁移提示词](../子系统级迁移提示词.md)、[单点功能迁移提示词](../单点功能迁移提示词.md)，不覆盖其既有 staged/unstaged 内容。运行规则以当前开发者指令、根与最近的 AGENTS.md 为准；本页和功能提示词仅用于指定迁移任务，不能扩大执行授权。

## 必须修正的旧假设

| 原始模板中的假设 | 使用时的修正规则 |
|---|---|
| 新功能一律放根 extensions/plugins | 先读 [architecture.md](../../docs/architecture.md)，落到既有 packages 组及 Cordis 扩展点；不创建并行运行体系 |
| director.ts/cell.ts 是 Orca 上游模块，可直接映射 SessionManager | 当前 stablyai 基线没有这些同名 src 文件；它们属于当前 Harness 自建 relay。按协议、调用和职责核实，不按名字翻译 |
| 所有 process.kill 换成 AbortController | 仅映射资源 owner 支持的取消；PTY、SSH、relay、ADB 与 LLM 请求分别处理，持久终端不能跟随单回合自动销毁 |
| 所有 Orca 进程逻辑都改为 LLM API | 只替换模型调用路径；终端、Git、设备、下载和远程 worker 仍有实际进程资源 |
| 缺依赖就用 Mock 实现产品流程 | Mock 仅限测试；产品展示 unavailable/disabled 与恢复原因，不能返回伪成功 |
| 开关与 Orca 完全一致即可 | 先确认字段真实存在、默认来源、scope 与持久化；设计不同必须明确记录，不能杜撰 api_key_model_discovery 等配置项 |
| 绝不允许改 core | 本任务不改 core；未来优先插件扩展。确需公共 API/生命周期变更时按仓库架构、消费者、SDK 和 snapshot 要求，经批准最小修改 |

## CLH 二开隔离

二开的产品身份为 Cinlan Harness（CLH），不是官方 DeepSeek Harness（DSH）。以下是后续实施约束，不表示当前产品已完成隔离；已核实缺口见 [CLI 差异分析](cli-control/差异分析.md)。本轮仅补充规则和提示词，不修改产品代码或根仓库规则。

| 对象 | 二开规则 |
|---|---|
| CLI 与启动 | 用户命令使用 `clh`；已有 `cinlan-harness` 长名可保留。沿用 profile-only launcher，不另造启动体系；二开安装包不得注册或覆盖官方 `dsh` 命令 |
| 环境与用户根目录 | 产品自有环境变量使用 `CLH_*`，用户根目录使用 `CLH_HOME`，默认 `~/.clh`；已有 `CINLAN_HARNESS_HOME` 别名须明确优先级。正常运行不得自动回退 `DSH_HOME` 或 `~/.dsh` |
| 持久化与资源 | profiles、settings、sessions、cache、credentials、logs 与 runtime 安装必须归 CLH 独立管理；所有默认值、显式配置、子进程环境、远程/WSL 路径及清理入口都要核对，不能只改显示文本 |
| 安装与运行标识 | 核对 product name、appId/bundle ID、移动 application ID、URL scheme、文件关联、IPC/socket、单实例锁、命令 receipt/backup、keychain service、browser localStorage/IndexedDB/partition、relay identity、更新源和遥测目标；与官方共用的标识必须列为缺口，不得沿用官方安装/更新/卸载所有权 |
| 发布坐标 | 二开发布包使用自有坐标，不冒用官方 registry package name；具体 scope、appId 等先列现值与拟用值，由 Yorker 确认，不凭空指定 |
| 上游名称例外 | 源码引用路径、第三方依赖名、既有 `@deepseek-ai/dsh-*` imports、TypeScript 符号和协议字段按实际代码保留；不能全局替换 `dsh` 为 `clh`。自有发布/持久化标识仍须隔离，内部名称不自动证明无冲突 |

每项迁移先输出“现值、拟用 CLH 值、owner、所有读写/安装/清理入口、兼容策略、验证方法”的映射表；无关标识注明不适用。实现时同步 CLI/SDK、Host/Client、installer、profile、CI 和双语示例中的相关消费者，不进行无关重命名。字段、配置 key 或持久化名称变化须按仓库类型、Session 版本与升级指引要求处理。

历史数据导入或命令兼容必须由 Yorker 显式批准，注明来源、目标和支持版本，备份并提供回滚；官方目录只读，导入不得覆盖或清理官方数据、凭据与安装收据。不能用隐式路径回退代替迁移，不能通过符号链接或配置别名默认共享官方用户根目录，也不能仅凭旧收据文件名接管官方命令。

验收必须覆盖官方 DSH 与 CLH 同机并存：只设置 `DSH_HOME` 时 CLH 不继承官方根目录；分别写入配置、会话、缓存与凭据后互不改变；同时启动不撞锁或 socket；安装、修复、升级、卸载 CLH 不改变官方命令、数据、凭据与安装记录。对实际受支持的平台保存收据，未运行的平台明确标注；文档检查不等于并存验收通过。

## 每次功能任务

1. 读取功能目录三份文件和固定上游源码；最新 main 更新时重采基线，不把旧 Orca/Cinlan fork 混入上游。
2. 在当前 Harness 查全部同类入口、所有调用者、Host/Client 字段映射、manifest、preset 和 profile 条件；不依据旧设计报告判断装配。
3. 输出功能映射、字段表、状态全集、资源/持久化 owner、CLH 标识映射、缺口与拟修改路径。分析请求只输出结论；多包/API/新依赖实施按授权确认。
4. 最小实现沿用 Cordis effect/typed events、settings slot/locale、Remote、LLM 和日志规则；跨层业务模块存在 MODULE-DELIVERY-GATE 时执行该规则。
5. 运行定向测试和实际 profile，保存 UI 与 backend 操作收据；只记录已运行命令，分清未运行、失败和通过。

## 状态口径

| 状态 | 定义 |
|---|---|
| 一致 | 同一用户能力、字段语义和关键状态已证实等价 |
| 部分实现 | 部分链路存在，但行为、入口或状态不完整 |
| 仅有底层能力 | 有 provider/service 或候选代码，尚无完整用户流程 |
| 缺失 | 在明确列出的检查范围内未找到完整等价实现 |
| 设计不同 | 目标相近，但执行、数据、部署或产品选择不同 |
| 待运行验收 | 需真实应用、网络、设备、打包或视觉证据才能下结论 |

六类不是线性完成率。每个档案当前是 source/profile 级结论；UI 检查表中的项目是验收要求，不是通过记录。
