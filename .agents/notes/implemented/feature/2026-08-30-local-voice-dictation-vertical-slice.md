# Agent Note: Local voice-dictation vertical slice (sherpa-onnx, Ctrl+Shift+E)

Status: implemented

English | [中文](2026-08-30-local-voice-dictation-vertical-slice.zh.md)

## Problem

Cinlan Harness had no offline speech-to-text capability, while the reference Orca IDE settings surface ships a Voice section with local model selection/download and a Ctrl+Shift+E push-to-talk/toggle dictation gesture. No STT engine, model distribution, audio-capture, or dictation-insertion code existed anywhere in this repository, and no prior Agent Note or existing package offered a directly reusable seam for any of these concerns.

## Decision

[Pinned resources and Host tasks](2026-09-14-voice-dictation-models-and-capture.md) supersedes this slice’s marker adoption, shared-request cancellation, and cache-lifetime decisions. This record retains the local-engine and client-ownership rationale.

A new `voice/` package group ships a provider-neutral Service Definition plus one Provider, following the `mobile-device` group's exact shape (registry class, `registerEngine`/`registerModel`, `HarnessError` subclass, opaque branded model id):

- **`@deepseek-ai/dsh-voice`** — `ctx.voice` registry: `registerEngine`/`registerModel`, `listDefinitions`/`requireDefinition`, and `engineOrUndefined` (distinguishing "no engine mounted" composition gaps from "model not downloaded yet" per-model state).
- **`@deepseek-ai/dsh-voice-sherpa-onnx`** — the Provider. It lazily `require`s `sherpa-onnx-node` exactly once and caches the outcome, copying the degraded-mode pattern in `@deepseek-ai/dsh-client-ui-better-sidebar`'s `pty-deps.ts` for `node-pty`: a missing or broken native addon never fails plugin load, and only `transcribe` fails (with a `VOICE_ENGINE_DEGRADED` code naming the load cause). `engine-repair.ts` also copies `pty-deps.ts`'s `findProfileDir`/`buildRepairCommand` pair to build a pasteable `dsh plugin --profile "<name>" install` command plus an `allowBuilds: sherpa-onnx-node: true` pnpm-workspace.yaml hint, served through the `engine.status` route method. Two shipped models — `sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23` (~74MB) and `sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20` (~511MB), both from the upstream k2-fsa/sherpa-onnx `asr-models` GitHub release — prove the full pipeline before the rest of the reference model roster (Parakeet, additional Zipformer languages, Whisper) is registered. Each sized model downloads through configurable concurrent HTTP ranges, retries transient failures under a per-range no-progress timeout that resets on each response chunk, preserves complete ranges across failures, assembles them into a temporary `.tar.bz2` archive, verifies the archive against the checksum published in the upstream release's `checksum.txt`, then switches to `extracting` and uses managed `ctx.subprocess` to run the platform's native `tar -xjf ... --strip-components 1`, avoiding the high-CPU pure-JavaScript decoder in production; an injectable JavaScript extractor remains for focused tests. One per-model operation and AbortController own cache inspection, download, extraction, and terminal cleanup, and concurrent callers await it. `models.remove` cancels and joins active work before deleting every cache artifact; Provider disposal also cancels and joins active work but preserves complete ranges for resume. A `.dsh-voice-ready` sentinel is written only after extraction settles; a failure is published only after partial cache files are removed. A complete older extraction missing only that sentinel is adopted after all required model files validate as non-empty, avoiding a full re-download; settled failures remain visible until retry. The Provider owns a loopback-only `/voice/api` Host route (`engine.status`/`models.list`/`models.download`/`models.remove`/`transcribe`) built on the generic `ctx.webServer.register` seam — the same route-registration primitive `@deepseek-ai/dsh-client-ui-better-sidebar` uses for `/sidebar/api` — with its own copied trust-fence and wire-envelope helpers (that package does not export them).
- **`@deepseek-ai/dsh-client-ui-voice-dictation`** — the client plugin: a Voice Settings section with one panel whose microphone, engine, and model rows share spacing, separators, and status treatment. It retains the two shipped models. The Engine sub-section (the `engine.status` load state, with a copyable repair command when degraded — the same `writeClipboard` one-click-copy primitive `@deepseek-ai/dsh-client-ui-settings-cinlan-capabilities`'s `InstallHint` uses for its bundle install command) and a Models sub-section (byte download, explicit install/extraction progress, ready/failure state), plus a microphone-permission control rehydrated from the browser permission or a persisted WebView fallback that changes only after an actual permission result, an always-visible microphone button registered through `conversation.input.right`, and a document-level Ctrl+Shift+E `keydown` listener. The button and shortcut share one reactive DictationController whose active operation belongs to the initiating session and that starts/stops a `MediaRecorder` capture, decodes it through `AudioContext.decodeAudioData`, resamples to 16kHz mono with a self-contained linear resampler, and appends the transcript to the current session's composer draft through `ctx.conversation` — the exact funnel `ui-better-sidebar`'s `conversation-draft.ts` uses for its @-reference button (copied, not imported, for the same reason: that helper is not exported). The microphone, Engine, and Models rows use the settings-panel layout while the Engine and Models independently read/render their own loading and error states, so a degraded engine never blocks the model list (downloading and caching a model has no native dependency).

Both `voice` and `voice-sherpa-onnx` are mounted in `@deepseek-ai/dsh-web-app`'s `cordis.patch.yml` beside `dsh-host-webserver` (the Web profile's single Host+Client bundle); `ui-voice-dictation` is mounted alongside the other generic Client plugins (`ui-settings-general`, `ui-conversation`) in the same file.

## Alternatives considered

**A cloud speech-to-text API instead of a local engine.** Rejected per direct user requirement: dictation must work fully offline.

**whisper.cpp bindings instead of sherpa-onnx-node.** Rejected because the exact model names in the reference Orca settings screenshot (Parakeet TDT v2/v3, Zipformer Bilingual/Streaming EN/ZH/KO, Whisper Tiny) are sherpa-onnx's own model-catalog naming convention; sherpa-onnx-node also ships official per-platform prebuilt native addons via `optionalDependencies`, matching this repository's `node-pty` distribution shape exactly.

**Capturing raw PCM directly via AudioWorkletNode instead of MediaRecorder + decode.** Rejected for this first slice: MediaRecorder is universally supported without a custom worklet script, and the decode-then-resample step is a small, independently testable pure function; a lower-latency AudioWorklet capture path is deferred until streaming partial-transcript support is added (see the `voice` package's Known Limitations).

**A swappable multi-Provider seam for `voice`, mirroring `mobile-device`'s Provider selection.** Rejected: there is one embedded local engine, not several competing backends a deployment chooses between at runtime; `registerEngine` accepts exactly one registration and throws on a second.

## Consequences

A user can download either shipped model, reopen Settings without losing the known microphone state, and start/stop offline dictation from either Ctrl+Shift+E or the visible composer microphone button. After downloaded bytes reach 100%, the UI exposes the native extraction phase and converges to ready or a retained failure reason. A degraded native addon is immediately actionable from the settings page — the same repair-command-with-copy-button pattern the terminal and capability-install surfaces already use — rather than a silent `transcribe` failure with no visible cause. The Host route, native extraction/cache lifecycle, and degraded-mode logic are independently unit-tested from the client capture/encode/settings/button logic; no test exercises real multi-hundred-megabyte network downloads or the real native addon. Expanding the model roster, adding a listening indicator, adding an engine-status re-check control, or adding streaming partial transcripts are deferred to future work per each package's Known Limitations.

## Testing

`voice`: engine/model registration, duplicate rejection, `engineOrUndefined` degraded-mode signal. `voice-sherpa-onnx`: lazy-load degraded mode (`sherpa-deps.spec.ts`), profile detection and repair-command construction (`engine-repair.spec.ts`), download/extract/failure/recovery state transitions over a real tiny `.tar.bz2` fixture (`model-cache.spec.ts`), managed native-tar subprocess invocation, the `/voice/api` route mounted on a real `WebServer` including `engine.status` and loopback rejection (`index.spec.ts`), and wire/trust helpers. `ui-voice-dictation`: Engine ready/degraded/copy-command states, Models download→install→ready convergence plus stale/failure handling, permission persistence across remount without conflating media errors with denial, the visible session-owned composer microphone button and slot lifecycle, the capture-decode-resample-encode pipeline against fake `MediaRecorder`/`AudioContext` doubles, the shared button/Ctrl+Shift+E round trip (fake microphone through fake transcription through a fake `conversation.input.for(actx).setDraft`), disposal during a deferred transcription proving quiescence without stale draft publication, and the built `lib/client.js` parsing and registering exactly one matching module factory. `apps/web/tests/settings-chrome.e2e.ts` boots the real Web composition and verifies the Voice settings section, browser microphone permission across Settings remounts, the static platform icon export, and the microphone button in a real session composer.
