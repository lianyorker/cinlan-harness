# Agent Note: Host-managed security skill resources

Status: implemented

English | [中文](2026-09-20-managed-security-skill-resources.zh.md)

## Problem

A visible research preset or loaded plugin does not prove that a complete skill resource exists. Resource downloads outlive individual Settings visits, and replacing files in place can invalidate relative references already returned to an Agent. Treating a bundled copy as a download also hides the absence of a real release source.

## Decision

The [Host resource manager](../../../../packages/security/security-skills/src/resources.ts) owns installation, re-download, update checks, updates, cancellation and removal. The [resource Remotes](../../../../packages/api/security-research-controller/src/index.ts) expose manager state and operations without storing another installation record. A request signal applies before admission; an admitted operation belongs to the manager. Leaving the page or reloading its controller ends observations, while explicit cancellation targets the observed operation id and waits for settlement. Manager disposal aborts and drains its owned work.

The [resource store](../../../../packages/security/security-skills/src/resource-store.ts) publishes immutable generations through an atomic active-pointer replacement under a writer lock. Downloading, archive checks, extraction and skill validation finish in private staging before publication. Failed or cancelled work before publication preserves the committed generation. Once atomic pointer replacement starts, commit wins: cancellation waits for settlement and can return the newly installed version; it does not roll back published state. Every activation and removal increments the active record revision, including an empty-state tombstone. Commit compares the operation’s expected revision, rejecting a delayed writer even when an intervening installation and removal leave both observations uninstalled. Generation rename preparation and atomic pointer replacement share the same short writer lock, so startup collection cannot remove a generation during publication. Startup recovery collects only inactive generations without live or unknown lease owners; it removes staging only when its owner is definitely dead.

The existing [Skill Provider](../../../../packages/security/security-skills/src/index.ts) registers the committed generation through the official registry and withdraws its registration when that generation changes or is removed. The [Web composition](../../../../packages/bundle/web-app/cordis.patch.yml) mounts the manager and global Provider so ordinary standard, PTC and Cordis Agents can discover installed skills; the optional research preset can contribute a nearer-scope Provider. A successfully loaded skill retains its generation lease across Provider reload: the global Provider holds it until Host-root disposal, while a scoped Provider holds it until its owning Agent realm is disposed. A standing preset realm can outlive a single Session, so Session completion alone does not release the files. Removal therefore stops discovery without deleting files still referenced by loaded work. Publication, lease acquisition and collection share the store lock so reclamation cannot race a newly acquired reader. A transient Provider refresh failure is logged and does not poison the refresh chain; a later resource notification can retry the current generation.

A configured release manifest supplies a content-derived version, exact archive size and SHA-256, sorted file inventory, skill inventory, platforms, license and provenance. The [archive validator](../../../../packages/security/security-skills/src/resource-files.ts) rejects invalid metadata, unsafe paths and corrupt or oversized contents. HTTPS is required except for controlled loopback HTTP. No public endpoint is inferred; without releaseManifestUrl, network operations remain unavailable with an explicit reason. Explicit bundled installation reads the package assets and records source kind bundled. The [shared inventory owner](../../../../packages/security/security-skills/src/resource-inventory.ts) applies the same filtering, UTF-8 normalization and content hashing to bundled installation and the [offline ZIP builder](../../../../scripts/build-security-skill-resource.ts). Neither path executes resource scripts or installs external tools.

The [Security Research page](../../../../packages/client/ui-settings-security/src/client/SecurityResourcesSection.tsx) is registered independently of the preset roster. It presents installed and available versions, source, progress, unavailable reasons, retry and explicit removal through framework-bound Host snapshots. Navigation disposes only its [observation](../../../../packages/client/ui-settings-security/src/client/resource-observer.ts). This page manages resources; assessment authorization and authenticated report delivery retain their separate owners. Installing skills grants no target, tool or export authority.

## Alternatives considered

**Tie installation to a page request.** Navigation and connection changes are observation events, not evidence that a user wants to cancel a download. Host ownership preserves admitted work and gives explicit cancellation one settlement point.

**Overwrite or delete the active directory.** Loaded skill content can include relative paths used after the original read returns. Immutable generations and realm leases preserve those paths while new discovery switches to the committed generation. This costs temporary disk retention until readers release their leases.

**Call a bundled copy a successful download or invent a release URL.** Both make source availability unverifiable. Explicit bundled provenance and a separately configured network manifest keep local availability and transport evidence distinct.

**Use resource installation to bootstrap MCP servers or present a scope/report console.** Resource files do not establish executable readiness or assessment authority. Reusing the existing MCP, Settings, scope and report owners avoids coupling a download transaction to unrelated installations and permissions.

## Consequences

The resource manager can remain available without a research preset or installed pack. Resource visibility comes from committed files, while assessment permission remains independently enforced by its Consumers. Old generations can consume disk while realms retain loaded paths; uncertain lease owners favor retention over unsafe deletion. Host shutdown ends an in-flight download rather than persisting partial transport progress. A crashed writer lock requires operator recovery after confirming its owner has stopped; PID age or a timeout does not authorize automatic lock removal.

The bundled resource contains 22 skill entries. [Provenance](../../../../packages/security/security-skills/assets/resource-provenance.json) and [NOTICE](../../../../packages/security/security-skills/assets/NOTICE) preserve known licenses and identify unestablished third-party revisions and permissions. Platform metadata describes readable resource files, not universal support for referenced tools. Missing bootstrap helpers remain an explicit limitation rather than a fabricated installer. No public resource release is established by this decision.

## Verification

The [manager tests](../../../../packages/security/security-skills/tests/resources.spec.ts), [store tests](../../../../packages/security/security-skills/tests/resource-store.spec.ts) and [archive tests](../../../../packages/security/security-skills/tests/resource-files.spec.ts) exercise generation switching, revision-based rejection of stale writers across empty-state transitions, startup collection, recoverable Provider refresh failure, retained relative files, cancellation, competing ownership and invalid archives. The [real Host Remote scenarios](../../../../packages/api/security-research-controller/tests/resources-lifecycle.host.spec.ts) cover disconnected observers, controller reload, manager disposal and explicit bundled installation; [missing-manager scenarios](../../../../packages/api/security-research-controller/tests/resources.host.spec.ts) pin unavailable behavior.

The [resource component tests](../../../../packages/client/ui-settings-security/tests/SecurityResourcesSection.client.spec.tsx) and [observer tests](../../../../packages/client/ui-settings-security/tests/resource-observer.client.spec.ts) pin visible states and observation disposal. The [Web resource scenario](../../../../apps/web/tests/security-resources.e2e.ts) uses a real loopback manifest and ZIP server for navigation, cancellation, failed-download retry, re-download, update, Host restart and removal. The [optional research scenario](../../../../apps/web/tests/security-capabilities.e2e.ts) retains scope and report backend checks and asserts the absence of scope/report controls on the resource page. These scenario definitions are not a claim that assembled Web execution passed; release verification records that result separately.

The [model-visible resource test](../../../../packages/security/security-skills/tests/model-visible.spec.ts) verifies a real Session request, skill tool result, reopened durable result and the managed bundled Provider; its expected output is [managed-security-skills.json](../../../../packages/security/security-skills/tests/expected/managed-security-skills.json). The [builder tests](../../../../scripts/build-security-skill-resource.spec.ts) verify archive contents independently, deterministic timestamps and line endings, unsafe-input rejection and real loopback transfer. The observed local build contains 503 files and 22 skills; its shared bundled inventory matches the ZIP descriptor exactly. This validates packaging without claiming a public download endpoint.
