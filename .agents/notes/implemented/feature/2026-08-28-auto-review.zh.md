# Agent Note: 可选的逐调用 Auto 审查

Status: implemented

[English](2026-08-28-auto-review.md) | 中文

## 问题

使用完全权限的用户需要可选的逐调用授权审查，同时保持默认权限不变，且不引入第二个审批策略来源。审查必须区分当前人类授权与历史事实，并在子智能体委派及 Session 恢复期间保持相同的权限范围。

## 决策

实验性 AutoReview profile bundle 使用当前智能体的 provider/model 审查每个原生调用与每个已开始的 PTC 内层调用。它需要外部安装，并针对单个会话显式选择。默认 profile 和未来会话设置不会启用它。Auto 共享完全权限的执行取值，而独立记录的预设标识决定调用是否需要审查。

已有权限与工具服务负责执行策略。审查器失败、决策格式错误、事实缺失和硬性拒绝都会停止工具主体；成功审查会委派给后续检查。即使存在显式授权，高风险敏感信息外传仍会被拒绝。当前人类指令优先于直接父智能体指令；检查点与历史操作只能恢复事实，不能授予权限。

## 生命周期与持久化

移除遵循参考生命周期：同步关闭准入、取消待定决策、将存活的 Auto 会话迁移到完全权限，然后在操作结束后撤销审查钩子。希望使用受限执行的操作员应在移除之前选择相应预设。冷恢复存储的 Auto 标识要求存在活动审查器；缺少 bundle 不能静默恢复其完全权限取值。进程内委派在首次 await 之前捕获 Auto/完全权限标识，并在 seed 与策略覆盖之后写入。其他进程后端保留自己的权限体系。

每个 PTC 绑定拥有其冻结的 schema；此临时元数据不会添加到开始/结束日志。结构化拒绝元数据包含稳定的错误名称、代码和可选原始原因，而主模型只看到固定拒绝消息。可选元数据不会更改 Session 格式 3，也不会改变 TypeScript/Python SDK 的循环投影。已发布代际保持不可变。mock Loader 测试序列化并冷恢复当前事件，保留原始原因且不向派生模型消息暴露它。

## 考虑过的替代方案

**独立审批服务。** 它会产生相互冲突的权限来源和隐式绕过路径。审查器因此参与已有工具流水线与权限预设生命周期。

**移植远程权限目录。** 本地合并投影已经提供会话选择。替换其 API 会将此可选能力扩展为不相关的远程服务与客户端更改；移植保留该 API，并要求外部层变更后重新启动 profile。

## 影响

模型授权可能误判操作，并消耗额外 token。外层 run_code 与直接 JavaScript 操作不在内层工具审查范围内，因此 Auto 不是确定性的安全屏障。本地合并权限投影保持不变；在 profile 停止时安装或移除外部层，然后重新启动以更新选择器可用项。不增加独立设置分节或专用拒绝卡片。

mock 测试覆盖带来源权限、格式错误与失败审查、后续否决、工具主体不运行的拒绝、绑定 schema 标识、取消、移除、重新安装、委派策略捕获及本地化风险确认。源码 Loader 组合在无模型/API 访问时验证真实智能体循环。这些验证针对集成，不认证真实模型风险分类或外部软件包发布。
