# Agent Note: 显式 SSH 客户端传输

Status: implemented

[English](2026-09-17-explicit-ssh-client-transport.md) | 中文

## 问题

Windows OpenSSH 不提供 [POSIX 执行提供方](2026-09-11-posix-ssh-runtime.zh.md)使用的本地主连接与 Unix 转发机制。Windows Harness 仍需向已安装的 POSIX 辅助程序发送经过认证的管理消息与独立二进制流。目标检查不能替代这些执行能力。

## 决策

连接归属方选择 POSIX OpenSSH 主机别名或显式 SSH 端点。显式传输使用维护中的 SSH2 exec 与 streamlocal 通道，仅读取配置的私钥文件，并要求配置 SHA-256 服务器密钥指纹。它不发现用户 SSH 配置或认证代理身份。远端辅助协议、摘要检查、TLS-PSK 流认证、心跳租期与提供方接口继续共用。

通道取消保留所有权，直到延迟分配关闭或连接丢失。通道打开无响应而到期时，连接失效，因为无法确认远端分配结果。未发布的已取消通道在结算前排空可读 EOF；已接受的流将取消责任转移给 TLS 包装流。

## 考虑过的替代方案

**要求 WSL 或本地 Unix 代理。** 这仅为复制 OpenSSH 控制套接字而引入第二个执行环境或本地监听端点。直接 streamlocal 通道保留既有远端端点协议，无需该部署依赖。

**把流移入管理 RPC。** 在辅助协议内复用字节需要新的流控，并将普通输出与控制进展耦合。独立 SSH 通道保留既有归属与认证决策。

## 影响

Windows 支持客户端角色，远端辅助程序及其文件系统／进程／沙箱提供方仍要求 POSIX。显式端点要求配置未加密私钥，并通过可信渠道分发指纹。不提供自动配置远端环境、远端 Windows 执行、重连或修改重放。[检查权限决策](2026-09-17-ssh-inspection-authority.zh.md)继续有效：目标检查不挂载执行提供方，也不建立远端 Session 权限。

POSIX 提供方决策继续负责预留、文件效果策略、认证流与断连未知结果。仅扩展其客户端传输限制；两份现行记录均未被完全取代。

## 验证

本机 SSH2 服务器夹具使用生成密钥、加密回环连接、真实协议子进程与 TLS-PSK 流端点。它们覆盖成功通信、主机密钥拒绝、流能力令牌拒绝、延迟取消及通道分配期间的释放。这些测试证明 Windows 客户端传输行为；原生辅助程序、文件系统、进程与沙箱验收仍要求配置 Linux/macOS 远端。
