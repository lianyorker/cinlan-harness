# Agent Note: 等待每个 Agent 的初始化

Status: implemented

[English](2026-09-09-awaited-agent-creation.md) | 中文

## 问题

共享预设分别为每个 Agent 安装工具和提示词片段。安装可能需要等待插件激活或外部资源。创建者必须知道这些贡献在 Agent 的首次模型请求前已经完成，取消也不能移除初始化器仍在使用的资源。

## 决定

`agent/created` 是工厂 setup 与注册表准入之后的串行初始化事件。每个监听器完成后才运行下一个；抛出异常或拒绝 Promise 会使创建失败并跳过后续监听器。载荷携带 `SessionStartSource` 与可选的工厂取消信号。调用方等待 `register()` 和 `announce()`；前者宣告全新启动并返回 disposer。本地 `agent/session-start` 仍是成功初始化后的同步通知，保留只观察启动而不阻塞它的消费方。

AgentLoop 在 setup 与创建分发期间保持 maintenance。输入可以在初始化期间进入收件箱，但驱动器仅在成功后启动。失败取消 maintenance 而不唤醒排队输入；有序拆除拥有收件箱清理。这样可在另一条拆除路径已移除收件箱投影时保留初始化错误。

监听器等待期间，创建分发保留作用域与 Session。Disposal 先取消初始化并等待分发完成，再释放这些资源。提供方将确切的作用域 disposer 嵌入其有序生命周期 effect，调用方拥有同一个 effect。因此任一所有者卸载都会等待同一静止点，作用域同时保留提供方的依赖上下文。监听器不得等待自身 Agent 的空闲状态或自身所有者的 disposal，因为两者都在等待该监听器完成。

本决策拥有异步创建时序。[作用域贡献者决策](2026-07-08-agent-scope-contexts.zh.md)保留注册可见性，[作用域运行时决策](2026-07-12-agent-scope-runtime-design.zh.md)保留注册表身份与拆除所有权，[拦截决策](../feature/2026-06-30-interception-extension-points.zh.md)保留策略与工具事件语义。

## 考虑过的替代方案

**单独的 setup 事件。** 现有创建监听器已经安装每个 Agent 的贡献。第二个初始化事件会拆分这项职责，却没有独立的消费方需求。

**分离的初始化。** 在插件激活完成前返回，会让首次请求缺少必需工具或上下文，也会让初始化失败脱离创建者。

**仅由调用方拥有有序拆除。** Agent 作用域是提供方拥有的子 fiber。仅将 disposer 嵌入调用方，仍允许提供方卸载在待完成初始化器结束前拆除该子 fiber。

## 后果

创建延迟包含异步初始化。失败成为调用方可见的创建失败，取消依赖监听器协作完成。已送达的通知仍然可见；回滚为已开始的创建宣告配对 disposal 通知。初始化期间注册仍然可见，因此调用方应等待创建 Promise 完成，而不是将注册表查询视为就绪。

该事件仅存在于进程内，不引入 Session 事件或 SDK 线协议通知。已发布的 Session 格式与已提交 SDK fixture 世代保持不变。聚焦生命周期测试覆盖串行完成、拒绝、两类所有者下的取消与独立并发创建；SDK 测试验证延迟的提示准入以及不变的规范事件投影。提示词安装器与 fixture 等待器测试覆盖就绪、拒绝和等待清理。
