# Agent Note: 带检查确认的侧边栏 Git 操作

Status: implemented

[English](2026-09-17-reviewed-sidebar-git-actions.md) | 中文

## 问题

侧边栏 Git 写入所操作的文件和暂存内容，可能在人们检查期间发生变化。浏览器提供的工作目录提示、过期的 Session（会话），或独立实现的传输处理器，都可能选中另一个仓库或绕过检查。与上游比较也需要明确的数据新鲜度策略：刷新远程引用会改变操作所需的网络与凭据条件。

## 决策

[侧边栏 Git 服务](../../../../packages/git/sidebar-git/README.zh.md)负责手动 Git 执行。强类型 [Remote 控制器](../../../../packages/api/sidebar-git-controller/src/index.ts)与侧边栏的 [Git 方法解码器](../../../../packages/client/ui-better-sidebar/src/git.ts)均委托给同一服务。[Host 组合](../../../../packages/client/ui-better-sidebar/src/index.ts)通过共享操作，将该解码器提供给 Connection Fetch 与可选 Web 别名路由。传输代码负责请求解码与错误映射，不另行拥有 Git 执行器。执行器缺失时返回不可用结果。

侧边栏客户端将生成的 `remote.sidebarGit` 命名空间声明为 Cordis 依赖。Remote 根服务本身不保证命名空间就绪；命名空间卸载时，也必须卸载捕获其方法的消费者。

### Session 与仓库权威来源

Git 操作请求标识一个已挂载的 Session。执行器从 Session 存储获取该实际对象，捕获其 cwd，并通过 Git 确定规范仓库根目录与 Git 目录。调用者提供的 cwd 不参与目标选择。变更请求携带所观察到的仓库根目录；排队操作在执行前重新检查已挂载的 Session、其 cwd 与仓库。仓库相对路径按字面处理，也适用于在仓库子目录中打开的 Session。

变更按规范根目录串行执行。破坏性操作还携带所观察到的 HEAD。这些检查将请求绑定到调用者检查过的仓库，防止已卸载或重新绑定的 Session 回退到服务器进程目录。

### 提交准备与确认

准备操作要求本地分支上存在已暂存变更，并拒绝尚未解决的索引冲突。它记录 Session id、cwd、规范根目录、Git 目录、分支、HEAD 与暂存条目指纹。它计算完整的预期消息，并在添加署名与末尾换行后检查最终消息限制。返回的预览就是展示给用户确认的消息。

可选署名使用 Git 的尾注格式化器，并保留现有尾注，包括签收署名。已有的标准共同作者尾注会被保留且不重复添加。需要插入时，若配置了尾注命令，或格式无法生成标准尾注，准备操作会拒绝继续，因此预览构造不会执行用户定义的尾注命令。[共享 Git 设置](../../../../packages/git/git-settings/README.zh.md)拥有该偏好；UI Host 不注册第二份 schema。

确认操作再次解析 Session 与仓库，并将记录的仓库、分支、HEAD 和暂存条目指纹与新快照比较。不一致时拒绝提交，要求重新检查。执行器通过 stdin 传入已检查的消息，以原样清理模式提交暂存索引，不暂存工作区编辑。

用户钩子与签名仍然有效。钩子可以拒绝提交或编辑消息，因此成功结果会回读并返回 Git 实际记录的消息。检查确认固定了交给 Git 的输入，不承诺抑制已配置的钩子行为。

### 缓存引用比较

显式比较操作选择本地可用的引用。启用上游比较时，优先使用当前分支缓存的上游；否则，或该上游不可用时，依次从 origin/HEAD、本地 main、本地 master 选择缓存的默认基准。结果标明所选基准，以及是否发生了上游回退。在三点差异计算之前解析双方提交，因此展示的比较会标出实际使用的提交 id。

尚无提交或已分离的 HEAD、缺失的默认分支或合并基准，都会产生明确的不可用结果。执行器不安排 fetch、pull 或 push。缓存引用可能过期；比较结果不表示远程服务器的当前状态。

### 限制与进程生命周期

[受管执行](../../../../packages/git/sidebar-git/src/process.ts)解析可执行文件，并将 argv、cwd、stdin 以及有界 stdout/stderr 收集交给已安装的子进程所有者。收集缺失或有损时拒绝返回结果。组装完成后，另一项字节检查覆盖完整序列化 Git DTO，包括仓库与预览元数据。

Remote 控制器传递调用者的取消信号。每条命令还观察其配置的截止时间与执行器卸载信号。完成等待同时涵盖命令结果与受管范围退出，命令结果被拒绝时也一样。卸载会中止活动操作，并等待它们完成。取消不会回滚已经完成的 Git 写入。

### Worktree 检查点

[Worktree Task](../../../../packages/workspace/worktree-task-git/README.zh.md)保留独立的创建与检查点语义。分支前缀在新建任务时生效，校验先于容量淘汰或 worktree 变更；已记录的分支身份保持不变。检查点保留其服务身份、检查点消息和既有钩子/签名选项。侧边栏署名不注入该路径或通用 Git 执行器。面向模型的 Git 工具集保持只读，也不引入回合结束时的提交行为。

## 考虑过的替代方案

**为每种传输保留原始 spawn 兼容执行器。** 独立 Remote 与 Fetch 执行器会重复实现仓库准入、索引检查、输出计量和进程生命周期规则。委托给单一执行器，使这些决策位于实际写入操作中，也让能力缺失明确可见。

**根据浏览器 cwd 或进程 cwd 选择仓库。** 这些路径不能确定请求所指已挂载 Session 的仓库。捕获的 Session cwd 与所观察到的规范根目录提供必要来源信息，排队后也保持这一要求。

**确认 Commit 时才构造最终消息。** 延后添加署名或重建消息可能改变用户检查过的内容。准备操作计算完整消息；确认操作检查仓库状态并复用该消息。

**为比较自动 fetch，或隐式刷新已检出的基准。** 这会给比较或创建偏好增加网络访问、凭据要求，以及其他 checkout 可见的潜在变化。比较使用缓存引用；本地基线刷新保持不可用，但仍保留可保存、可重置的设置。

**将用户提交偏好应用于提供方检查点。** 检查点捕获提供方拥有的任务状态，并使用独立身份与生命周期。在其中复用侧边栏署名或用户钩子/签名策略，会改变这些快照的含义。

## 结果

单一执行器使不同传输的行为与拒绝条件一致，显式预览让自动署名可被检查。代价是额外 Git 读取、独立确认步骤，以及捕获状态变化后重新检查。输出限制可能拒绝过大的状态、差异或消息，避免将不完整数据呈现为完整结果。

变更队列只协调此执行器的操作。仓库检查及随后的 Git 写入，与无关 Git 进程之间不构成原子事务。其他进程可能在检查后改变引用或索引，钩子也可能改变最终结果。因此，操作失败或取消不代表仓库未变；调用者通过新的仓库观察进行后续操作。
