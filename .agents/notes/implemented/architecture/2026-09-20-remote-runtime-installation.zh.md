# Agent Note: 远程运行时安装与激活

Status: implemented

[English](2026-09-20-remote-runtime-installation.md) | 中文

## 问题

远程执行需要相互兼容的 helper、PTC bootstrap、依赖树和原生二进制。只复制入口文件会使包解析和原生执行依赖远端账号的环境安装。更新共享目录可能改变既有 Session 捕获部署所指向的可执行字节。

安装也会超出浏览器观察的生命周期。将取消绑定到设置页的流会让刷新产生破坏性影响，而将流丢失视为清理成功会掩盖未知的远端结果。并发目标编辑还可能使已验证运行时基于陈旧的信任或部署坐标被激活。

## 决策

[execution-runtime 服务](../../../../packages/execution-host/execution-runtime/README.zh.md)独立于执行租约和 Client 观察者拥有安装操作。每次显式安装／更新捕获一个目标 ID／修订号与部署请求，并立即返回带品牌类型的任务 ID。观察和取消都需要该 ID。关闭观察者只会脱离观察；Client 刷新后连接到同一 Host 可恢复有界的保留任务列表。显式取消等待任务结束，服务 dispose（资源释放）则取消并等待全部所属工作完成。

任务回执是 Host 内存中的观察结果，不是持久任务。Host 进程重启会丢失列表，也不会恢复安装。这将恢复保证限制在服务实际保留的权限范围内：持久目标激活记录所选部署，但该记录和浏览器回执都不能证明中断的远端进程状态。

### 固定的完整世代

发布 manifest（元数据清单）固定版本、源码修订、协议、目标平台／架构、入口路径，以及每个普通文件的大小、SHA-256 和可执行标志。产物包含完整运行时依赖闭包，包括原生系统和 PTY 二进制。发布生成器在记录源码修订前拒绝已跟踪或未跟踪的变化；被忽略的目标构建输出仅在通过原生验证后进入产物，并由 manifest 独立固定哈希。生成器消费已安装且已构建的输入并固定依赖版本；安装不在远端执行包管理器解析，也不访问 registry。缺失或不兼容的发布产物会报错，不会因此允许使用环境中的包。

可执行标志属于目标元数据。Windows 控制端的文件模式无法可靠识别 POSIX 可执行文件，因此生成器显式标识目标可执行文件，并验证原生目标字节。上传权限和发布文件权限遵循已封存的元数据。现有 Node 和账号拥有的私有安装根目录仍是部署前提。

显式 SSH 端点固定服务器密钥，并指定 Host 私钥文件。每个操作拥有连接、SFTP 通道、监督程序和随机 staging 目录。本地验证、传输时复查和远端验证覆盖完整文件列表。远端监督程序通过控制描述符执行部署后的 PTC 子进程，并验证 helper 身份；原生 PTY 和沙箱探测独立于哈希检查验证行为。安装器探测运行固定的验证代码，不运行模型提供的代码。

通过验证的 staging 树以目录重命名发布到 `generations/<manifest SHA-256>`。安装服务保持世代不可变：服务不覆盖或回收已发布世代。这是安装保证，不是针对恶意远端操作系统或账号所有者的可信证明。

### 激活与既有 Session

发布先于保存目标修订号的比较并交换。目标持久化提交是激活提交点。即使留下完整但未使用的世代，陈旧修订号也不会改变当前目标。激活在目标修改队列中等待时，取消会阻止选择。持久写入一旦开始，取消不会撤销成功提交，也不会将其结果改写为取消。

托管激活为既有捕获绑定保留前驱执行配置。活动租约保留准入时的部署，继续使用其中的 helper／PTC 路径和哈希。冷 Session 可以解析显式保留的激活修订号；普通目标编辑会使保留授权失效。保留全部历史信任配置会静默保留操作员有意替换的凭据或信任，因此世代保留和授权保留必须区分。

传输丢失会使观察失效，不能证明远端清理完成。取消等待操作可观察的结果，并仅关闭所属资源。自动重试未确认的修改不是恢复协议。

## 考虑过的替代方案

- **管理流关闭时取消。** Client 刷新或观察者切换会在没有显式意图的情况下取消 Host 拥有的有效工作。
- **将任务回执视为跨重启持久任务。** 可靠的重启恢复需要持久操作身份、远端结果核对，以及超出内存任务映射的清理权限。
- **在远端安装依赖或只复制 helper 入口文件。** registry 状态、可选原生选择和环境模块路径会在选定发布产物后决定实际执行的字节。
- **从控制端文件推导 POSIX 模式。** Windows 模式位不能保留沙箱和 PTY 二进制所需的目标可执行元数据。
- **原地替换共享的当前目录。** 既有租约可能观察到变化后的代码，目标修订号检查也无法保留其捕获世代。
- **激活后删除前驱。** 其他 Host 或冷 Session 可能仍保留前驱；本地任务完成不能证明全局不再使用。

## 影响

安装增加显式发布生产和原生验证成本。缺失的生产依赖或目标预构建产物会阻止生成可用发布；安装器不下载二进制、不升级 Node、不创建账号，也不建立安装根目录。在独立且理解引用的回收设计能够统计其他 Host 和保留 Session 之前，世代持续占用存储。

[POSIX SSH 提供方记录](2026-09-11-posix-ssh-runtime.zh.md)继续保留独立的流安全、预留、租约和断开语义理由。自动产物部署由本独立安装服务拥有；提供方系列保留其执行职责。[不可变 Session 绑定记录](2026-09-20-immutable-session-execution-binding.zh.md)继续负责持久选择、准入和执行隔离。[异步沙箱与路径记录](2026-09-11-async-sandbox-execution-world-paths.zh.md)继续负责准备时序、取消和提供方拥有的路径身份。没有任何记录被完全替代，也没有记录满足合并或归档条件。

## 验证

[部署测试](../../../../packages/execution-host/execution-runtime/tests/provisioning.spec.ts)覆盖加密 SSH/SFTP 传输、manifest 篡改、依赖完整性、staging 归属和子进程控制。[任务测试](../../../../packages/execution-host/execution-runtime/tests/tasks.spec.ts)覆盖经 Loader 准入的归属、观察者脱离、同 Host 列表恢复和目标修订竞争。[激活竞争测试](../../../../packages/execution-host/execution-runtime/tests/activation-races.spec.ts)通过直接取消信号、经 Loader 准入的运行时取消及 fiber dispose 覆盖真实目标修改队列，并在持久化已经开始后保留成功提交。受控传输对端和替代的 helper 行为只构成有限证据，不能证明原生 POSIX 验收通过。

所需原生证据包括使用完整目标产物的冷安装与更新、部署后的 PTC 执行、真实 PTY I/O、沙箱强制执行，以及既有 Session 租约连续性。Windows 生成器证据必须独立于本地模式位验证目标可执行元数据。此处未记录真实 POSIX 验收结果；产物生产和原生验证需要集成负责人提供 Linux/macOS 环境，以及匹配的发布依赖和二进制。
