# Agent Note: 由实际消费功能持有浮动窗口与快捷键调度

Status: implemented

[English](2026-09-17-floating-workspace-command-ownership.md) | 中文

## 问题

`floating-workspace` 保存窗口偏好，`keybindings.overrides` 保存命令偏好。已保存的记录不能建立真实窗口、编辑器操作或终端消费者。把每个已保存命令都显示为可用，会承诺当前挂载功能无法执行的操作。

第二个视图还需要明确由谁持有其 Session 选择、原生窗口与终端身份。打开它时必须保留应用组合和已有 Session，同时允许打开者、设置 owner 与操作系统分别结束其生命周期。

## 决策

### 现有应用的一个子窗口

浮动工作区通过现有传输打开同一应用产物。Web 复用当前 origin 与应用路径；Electron 复用已安装的 `dsh-app` 文档和现有 preload。子窗口通过受限路由接收经过校验的窗口 UUID 与来源 Session id。它在会话目录就绪后选择该已有 Session 一次，之后保持正常的独立导航。打开此视图既不创建 Session，也不增加第二个 Host 或前端。

每个打开者持有一个确切的子窗口句柄。启用偏好只让打开操作可用；窗口由显式用户操作创建。获接受的禁用、owner 释放、页面退出和原生 Host 关闭都会关闭所持有的子窗口。正常关闭子窗口时，焦点返回仍连接到文档的触发控件。位置变更移动打开入口，宽高变更则作用于下次打开。子窗口提供关闭控件，并省略打开入口与浮动切换命令，从而阻止递归创建窗口。

设置分区在一张偏好卡片中展示启用状态、终端目录和入口位置，不展示窗口尺寸，也不提供第二个打开/关闭操作。持久化的宽高仍是下一个子窗口接受的运行时字段，窗口创建则由应用外壳入口与已注册快捷键持有。

Electron 的主窗口策略按预期文档、frame 名称、路由字段和受限窗口参数准入此子窗口。它保留沙箱，并把实际创建的子窗口 webContents 返回给 Electron。导航、重定向和后续窗口创建不能把子窗口变成另一个原生启动器。插件管理器与无关窗口的策略保留各自限制。浏览器拒绝与平台能力缺失分别保持明确的受阻或不可用状态。

### 命令归实际消费者所有

[键盘服务](../../../../packages/client/keyboard/README.zh.md)持有命令注册、有效绑定、校验与匹配。各功能提供本地化命令元数据、默认绑定、作用域、可用性和 disposer。现有 Lexical 输入框处理器、CodeMirror 保存与搜索处理器以及应用外壳处理器向 matcher 查询事件，再执行各自的操作。本地焦点、补全、输入法组合和提交规则仍决定操作能否执行。主视图持有 `floatingWorkspace.toggle`，默认绑定为 Ctrl+Shift+Space。

显式覆盖会替换已注册的默认绑定；null 绑定表示取消绑定。没有已挂载命令的持久化 id 仍显示为不可用，并在无关编辑中保留。因此，旧记录保留偏好，但不安装操作。保留组合与冲突会明确报告，不会静默改写。录制仅作用于当前录制控件；重置移除用户覆盖，让 owner 默认值或配置的基础值重新参与解析。

### 在创建标签页时捕获终端上下文

浮动上下文在偏好加载完成之前就提供经过校验的窗口身份。因此，侧边栏状态从创建开始就能使用正确的窗口命名空间，无需临时与主视图共享。只有真实终端消费者声明目录支持。新的浮动终端标签页同时捕获窗口 id 与获接受的目录；加载中或不可用的偏好不能提供暂定目录。捕获的数据在渲染与重连期间随该标签页保留，后续偏好变更作用于新标签页。空目录表示请求关联 Session 的工作目录。终端执行与目录校验仍由[原生运行时消费者决策](2026-09-17-native-settings-runtime-consumers.zh.md)所述的终端 owner 负责。

持久化遵循 [Host 偏好决策](../bug-fix/2026-08-06-host-backed-web-preferences.zh.md)，已安装运行时的归属遵循[桌面打包决策](2026-08-25-electron-desktop-packaging-and-updates.zh.md)。已归档的 [Lexical 编辑器决策](../../archived/architecture/2026-08-20-web-composer-lexical-editor.md)提供选择编辑引擎的历史背景；[当前对话参考](../../../../docs/subsystems/conversation.zh.md)持有其受支持行为。这些记录保留各自关于持久化、分发和编辑的独立理由。

## 曾考虑的替代方案

**独立的浮动前端或 Desktop HTTP 服务。** 两者都会为同一 Session 的额外视图增加另一套应用组合或传输。复用产物可以保留已安装客户端、认证和功能 owner。

**由已保存 id 驱动的全局快捷键分发器。** 它无法确定编辑器、输入框弹出层或功能能否执行操作，还可能与焦点所在的处理器争抢事件。注册暴露真实能力；匹配将执行与事件裁决留给消费者。

**从最新渲染的设置派生窗口身份或终端目录。** 身份会晚于侧边栏状态可能创建的时间到达，后续偏好也可能在重连时改变已有标签页。提前提供身份并在创建时捕获目录，可以保留窗口、标签页与 Session 的关联。

**从设置页启动子窗口并编辑其尺寸。** 设置页持有的操作会重复应用外壳命令及其焦点恢复路径，可编辑尺寸还会暗示浏览器或操作系统无法保证的精度。紧凑设置页只编辑命令位置与终端初始化所需的偏好；持久化尺寸仍可供部署配置与运行时使用。

## 影响

插件卸载会一并撤销其命令、订阅和窗口贡献。不可用的持久化命令仍可查看，但不会假装执行。设置分区包含三个可搜索行，不含启动或尺寸控件。平台策略可能拒绝窗口或调整请求的几何尺寸，因此打开入口必须报告实际结果。额外视图共享持久化 Session 数据，同时保留独立的视图状态与资源生命周期。

窗口与键盘偏好记录不增加模型可见提示或 Session 事件。被调用的输入框、编辑器和终端操作保留现有 owner 的行为与权限。窗口 UUID 区分视图和终端归属；终端访问仍与其 Session 关联。
