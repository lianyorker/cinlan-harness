# Agent Note: 持久自动化需要独占本地所有权

Status: implemented

[English](2026-09-17-durable-automation-ownership.md) | 中文

## 问题

保存计划不能确定哪个进程有权调度，也不能确定一次失败的启动是否已经创建 Agent。若调度器将到期时间等同于执行许可，多 Host 进程、时钟变化、部分持久化和进程退出都可能造成重复工作。提交失败后，设置页也不能根据陈旧快照推断成功。

## 决策

[自动化运行时](../../../../packages/automation/automation/README.zh.md) 在规范化 Harness home 与真实启动 profile 下拥有持久定义、调用认领和历史。独立 SQLite 所有权数据库以零忙等待超时持有一个生命周期事务。第二个进程显示不可用，不执行恢复或调度。状态写入使用另一个数据库。关闭等待期间仍持有所有权。

接受的执行时刻先提交唯一标识、冻结执行输入和游标，随后才通过公开 API 创建 Agent。提交失败会锁定为存储不可用，因此移除外部故障不会隐式恢复结果不确定的准入。显式手动令牌使准入保持幂等；计划与手动重叠分别产生可见结果。UTC 重复规则不在启动时补跑，已提交游标不会回退。

每次调用使用显式 Workspace、模型、Agent 预设和权限输入创建普通 Agent Session。访问 Host 路径前及发布时都会检查 Workspace 执行身份；SSH 路径恰好存在于本地并不授权 Host 执行。profile 提供执行绑定时，设置阶段记录显式本地选择，并将其最终提交纳入 Agent 发布事务。未提供该服务的 profile 保留普通本地设置流程。发布前完成设置，任务经正常的用户消息日志路径进入会话。默认值不会替代缺失的已保存引用。预设 id 仍选择当前文件组合。[Controller](../../../../packages/api/automation-controller/README.zh.md) 与 [页面](../../../../packages/client/ui-settings-automation/README.zh.md) 通过既有 Remote 和框架观察机制公开已提交状态。

恢复不重放启动或结果不确定的工作。它记录 ambiguous 或 interrupted 证据，暂停定义供人工检查，并保留调用历史。整个 Host 关闭时，持久化可能在正常结束记录落盘前卸载；此状态记为中断，不虚构取消或成功。活动状态不明确时，运行时使用已确认的 flush 参与和持久 Session 证据。

此决策补充 [Session 内提醒](../feature/2026-08-05-durable-web-schedule.zh.md) 与 [显式提醒时区](../simplification/2026-08-09-explicit-schedule-time-zone.zh.md)。这些记录继续拥有既有 Session 内的交付。保存的自动化拥有独立 Agent 调用；两个旧决策均未被取代。

## 考虑过的替代方案

**按时间过期并夺取租约。** 暂停或过载进程可能在租约过期后仍存活。SQLite 进程所有权在进程真正退出时释放，不让另一进程猜测原所有者何时停止。

**重启后重放未完成工作。** Agent 创建和外部任务效果无法与调度日志构成原子事务。重放不确定的启动可能重复用户工作。可检查的恢复保留此不确定性。

**复用活动 Session 或继承当前默认值。** 调用来源和权限将依赖无关用户活动。显式保存输入与新 Session 使每次调用可识别。

## 后果

调度需要运行中的本地 Host、支持 SQLite 操作系统锁的本地文件系统，以及每个 home/profile 的唯一所有者。UTC 每小时、每天和每周重复规则覆盖已实现编辑器。操作系统唤醒、守护进程安装、远程调度、自定义 cron、本地时区、补跑与历史保留控件不在本实现范围内。配置与完整限制归包 README 所有。

验证使用独立进程检查所有权竞争与崩溃释放，使用真实 Loader 组合检查 Agent 生命周期及关闭，并以真实 SQLite 触发器故障检查提交拒绝。失败用例证明未创建 Agent、未提交调用记录，并且准入会保持停止直到显式重启。Client 与 UI 测试覆盖原始已提交状态流、revision 冲突、操作反馈和释放。完整浏览器验收仍是单独的产物检查。
