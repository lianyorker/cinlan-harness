# 项目进度与差异总览

## 结论

当前 Harness 有 LLM/Session 底座和较多终端、设置、远程执行、语音、移动通信代码，但不能视为 Orca 功能已完整迁移。主要缺口是实际装配、跨入口字段/状态对齐、移动端真实后端，以及 Orca 特有的编辑器、快捷命令、分享和端口管理流程；设计不同的功能不应按一比一移植计算完成度。

本次完成分析文档，不完成产品实现。按独立设置/用户任务建立 [49 个功能目录](README.zh.md)，每个目录含源码差异、UI 检查和对应迁移提示词；宽范围目录负责协作关系，快捷键、MCP、模型发现、Design Mode 等可独立执行项有各自目录。覆盖以源码片段、设置导航和 README 主要功能为边界，不宣称穷尽上游所有命令、开关或平台细节。

源码级分类为：27 项部分实现、11 项设计不同、6 项仅有底层能力、4 项在检查范围内缺失、1 项待运行验收。这不是完成率；所有项目的运行/视觉等价性仍需专项收据。

## UI 检查重点

Orca 更围绕并行外部 Agent、worktree、终端与原生/远程 Host；Harness 更围绕 API LLM、Session 日志、工具结果和插件 slot。比较应以用户任务为单位，而不是菜单标题或组件数量。

- 设置：组/section/anchor、搜索定位、条件隐藏、真实 readback、保存失败、只读和 capability 状态。
- 工作区与会话：创建/继续/fork/审批/停止、Host 路由、dirty 删除、长列表、并行状态与恢复。
- 工具区：canonical/legacy 入口、terminal tab/split、文件编辑/预览/Diff、browser guest 与权限。
- 移动端：真实 Host 数据、断线/重连、审批、mock 禁用、文件/浏览器/终端 capability 与原生权限。
- 通用：zh/en、明暗主题、长文本、200% zoom、桌面/窄窗/手机、焦点与可访问性；每个目录有专项 UI 表。

## 建议顺序

先做 [CLH 标识映射与官方并存验收](提示词使用规则.md#clh-isolation)，再交付以下功能；不要把 CLI 显示名已改为 clh 视为命令、发布和数据隔离全部完成。

1. 修复或确认快捷键设置链，解析实际 Web/Desktop profile，贯通已存在设置/任务/编排入口。
2. 对 Session、工作区、终端、远程 Host、mobile pairing/relay 做同类路径和端到端验收。
3. 补第三方 provider/状态矩阵、真实移动后端、文件/Diff 与语音可用性。
4. 按产品决策扩 quick commands、Skill sharing、sparse、端口、VM 与 AI Author，不恢复重复管理器。
